# ME-Hub v3.0.0 测试网全流程升级手册

本文描述如何搭一条 **Hub v2 → v3.0.0 原地升级** 的测试网，并同步升级 RollApp 侧的 **dymint 2D → 3D**。目标是把 settlement（rollapp / sequencer / delayedack / eibc / IBC lightclient）和 sequencer 出块、IBC 转账整条链路跑通。

RollApp 业务模块（check-in、KYC 等）本身不变；需要换的是 settlement 上的 schema，以及 RollApp 节点里的 dymint store / 二进制。

---

## 1. 范围与结论

| 组件 | 升级前 | 升级后 | 备注 |
| --- | --- | --- | --- |
| Hub (`med`) | SDK 0.47 + IBC v7 | SDK 0.50 + IBC v8，`UpgradeName = v3.0.0` | **原地升级**，不要用 v3 二进制重新 `init` |
| Hub store | 无 `lightclient` | 只 **新增** `lightclient` | `consensus` 在 v2 genesis 已存在，**禁止**标成 Added |
| RollApp (`rollappd`) | SDK 0.46 + IBC v6 + 旧 dymint | 仍是 SDK 0.46 + IBC v6，dymint **v1.6 (3D)** | 业务逻辑不变 |
| dymint | 2D store（`DrsVersion == 0`） | 3D store + DA/DRS 写入 state | **离线**跑 `run-3d-migration` |
| Relayer | 能打 IBC v7 Hub | [dymensionxyz/go-relayer](https://github.com/dymensionxyz/go-relayer) `main-dym` | Hub 升到 IBC v8 后必须换兼容 relayer |

**推荐顺序（不要颠倒）：**

```
v2 Hub 出块
  → 注册 RollApp + Sequencer（用 v2 CLI）
  → 旧 rollappd 出块、提交 state update
  → （可选）打通 IBC
  → Hub gov：software-upgrade v3.0.0
  → Hub halt → 停 RollApp → 换 med-v3 启动
  → 确认 handler 跑完
  → dymint run-3d-migration（DA=me-da）
  → 换新 rollappd 启动
  → 重启 relayer，验收 IBC / lightclient
```

Hub halt 期间 settlement RPC 不可用，RollApp 应一起停。不要在 Hub 还是 v2 时就换新 dymint，也不要在未做 3D migration 时直接起新 `rollappd`。

## 2. 链上升级实际做了什么

`UpgradeName` 必须一字不差：`v3.0.0`（见 `app/upgrades/v3/constants.go`）。

Handler（`app/upgrades/v3/upgrade.go`）在 **PreBlock** 执行，顺序固定：

1. `RunMigrations()`（SDK 0.47 → 0.50，含 gov 4→5）
2. 把 CometBFT consensus params 从 `x/params` 迁到 `x/consensus`
3. 修正 gov expedited 参数（denom / 周期）
4. sequencer params：`min_bond` + `unbonding_time` → `notice_period` + liveness/dishonor  
   - 旧 `unbonding_time` 会写进新 `notice_period`
   - 旧 `min_bond` 交给 rollapp：`params.min_sequencer_bond_global`
5. rollapp / delayedack / eibc params 迁到各自 module store
6. rollapp registered denoms 迁到独立 keyset（必须在改写 rollapp 对象之前）
7. rollapp 对象 v2 → v3：`transfers_enabled` → `transfer_proof_height`；已有 `channel_id` 的视为已 launched
8. 回填 sequencer 的 dymint-addr / proposer 索引，并把存量 bonded sequencer 标成 `OptedIn=true`
9. 按已有 IBC channel 回填 canonical light client

漏跑 handler 时，后续 BeginBlock 会在 IBC v8 client params 上 panic。v3 二进制必须 `app.SetPreBlocker(app.PreBlocker)`（已在 `app/app.go`）。

## 5. Phase A — 用 v2 搭基线测试网

**必须用 v2 镜像做 `init`。** 当前仓库的 `scripts/src/genesis_config_commands.sh` 已按 SDK 0.50 改过，直接喂给 v3 镜像会写成 v3 genesis，不是升级测试。服务器 drill 用 `scripts/setup_v2_upgrade.sh`（source `scripts/src/genesis_config_commands_v2.sh`），通过 Docker 跑：

- v2：`ghcr.io/openmetaearth/med:v2.0.17`
- v3：`ghcr.io/openmetaearth/med:v3.0.0`

宿主机需要 `docker` 和 `jq`。链数据在宿主机 `HOME_DIR`（默认 `~/.mechain-upgrade`），容器内挂到 `/root/.mechain`。

### 5.1 启动 Hub v2


### 5.2 初始化并注册 RollApp（v2 CLI）

v2 的 `create-rollapp` / `create-sequencer` 参数和 v3 **不兼容**。基线阶段用仓库里现有脚本即可（它们仍是 v2 语法）。


创建 sequencer 账户并打币、注册：




### 5.3 启动旧 RollApp，确认 state update

```bash

```


同时用业务命令确认 RollApp 本身可用（check-in / KYC 等，按你们现网路径）。

### 5.4 （强烈建议）打通 IBC

升级 handler 会把已有 `channel_id` 的 rollapp 标成已开通转账（`transfer_proof_height != 0`）。**基线就建好 channel**，才能验证「升级后旧 channel 仍能转账」，而不是只验证「升级后再新建」。

顺序（lightclient 模块约束，升级后同样适用）：

1. 创建 light client
2. 等 sequencer 再交一次 **高于 client 高度** 的 state update
3. 再建 transfer channel

```bash
# 资金：relayer 在 Hub 用 umec，不要用脚本里残留的 udym
cd /Users/aris/xingdao/me/rollapp
# 按实际 RPC / chain-id 改 scripts/ibc/setup_ibc.sh 后执行
sh scripts/ibc/setup_ibc.sh

rly start hub-rollapp
```

建 client 前可把 dymint `batch_submit_time` 临时调短，让 state update 尽快上 Hub。

时间关系（v2 叫 unbonding，v3 叫 notice period，数值应被 handler 原样带过去）：

```text
dymint max_idle_time  <  IBC trusting period  <  sequencer unbonding/notice period
```

```bash
med q ibc channel channels
med q ibc client state 07-tendermint-0
```

做一笔 Hub ↔ RollApp ICS20，记下 channel id 和成功 tx。

## 6. Phase B — Hub 原地升级到 v3.0.0

### 6.1 备份

```bash
med tendermint unsafe-reset-all --keep-addr-book   # 不要在升级路径执行 reset
# 正确做法：停节点前拷贝整个 home
systemctl stop med    # 或 Ctrl-C 前先备份
cp -a "$HOME/.mechain" "$HOME/.mechain.bak-$(date +%Y%m%d%H%M)"
```

多节点：每个 validator 都备份 `data/` + `wasm/`。

### 6.2 提交 software-upgrade（仍用 med-v2）

先看当前高度，选一个足够远的 halt height（本地可 +40～80；公开测试网按投票期 + 缓冲）：

```bash
H=$(med status --node tcp://127.0.0.1:36657 | jq -r '.sync_info.latest_block_height')
HALT=$((H + 50))
echo "halt height = $HALT"
```

```bash
med tx gov submit-legacy-proposal software-upgrade v3.0.0 \
  --title "v3.0.0" \
  --description "ME-Hub SDK 0.50 / IBC v8 / settlement v3" \
  --upgrade-height "$HALT" \
  --upgrade-info '{"binaries":{}}' \
  --no-validate \
  --deposit 100000000umec \
  --from global_dao \
  --keyring-backend test \
  --home "$HOME/.mechain" \
  --chain-id mechain_2401-1 \
  --gas auto --gas-adjustment 1.5 \
  --fees 200000000umec \
  --yes
```

- `--upgrade-info` 与 `--no-validate`：v2 CLI 在 info 为空时会拒单。
- plan **name 必须是 `v3.0.0`**，与 `app/upgrades/v3/constants.go` 一致，否则 halt 后 v3 二进制找不到 handler。

投票（所有有权投票的 validator）：

```bash
PROPOSAL_ID=<id>
med tx gov vote "$PROPOSAL_ID" yes \
  --from global_dao --keyring-backend test \
  --home "$HOME/.mechain" --chain-id mechain_2401-1 \
  --fees 200000000umec --yes
```

确认：

```bash
med q gov proposal "$PROPOSAL_ID"
med q upgrade plan
```

### 6.3 Halt

高度到达 `$HALT` 后 v2 进程会停在：

```text
UPGRADE "v3.0.0" NEEDED at height: ...
```

此时：

1. 确认 Hub 已停
2. **立刻停 RollApp**（`rollappd stop` / kill），避免 settlement 断开后本地继续堆无法提交的 batch
3. 停 relayer

### 6.4 换成 med-v3 启动

```bash
# 二进制替换（systemd ExecStart 或 PATH）
ln -sf /usr/local/bin/med-v3 "$(go env GOPATH)/bin/med"

# 确认 libwasmvm v2 已就位
med start --home "$HOME/.mechain"
```

Cosmovisor 用法：把 `med-v3` 放到 `$DAEMON_HOME/cosmovisor/upgrades/v3.0.0/bin/med`，plan name 与目录名一致即可自动切。

启动后日志里应依次出现类似：

```text
migrated consensus params from x/params to x/consensus
updated gov expedited params after Migrate4to5
migrated sequencer params to module store
migrated rollapp params to module store
migrated delayedack params to module store
migrated eibc params to module store
migrated rollapp registered denoms to keyset
migrated rollapps to v3 schema
backfilled sequencer dymint-addr and proposer indexes
migrated rollapp canonical light clients
upgrade finished successfully.
```

然后区块高度继续增长。若直接 panic `client params` / `GetParams`，多半是 PreBlocker 没挂上或跑的不是带 handler 的二进制。

### 6.5 Hub 升级后立刻核对

```bash
med status
med q upgrade applied v3.0.0

# sequencer：不再有 min_bond / unbonding_time
med q sequencer params
# 期望含 notice_period（数值 = 升级前 unbonding_time）

# min bond 在 rollapp params
med q rollapp params
# 期望 min_sequencer_bond_global

med q rollapp show-rollapp "$ROLLAPP_CHAIN_ID"
# genesis_state.transfer_proof_height != 0（若基线已有 IBC channel）
# launched = true

med q sequencer sequencer <sequencer-addr>
# opted_in = true

med q lightclient light-client "$ROLLAPP_CHAIN_ID"
# 若基线已有 client，应能看到 canonical client id

med q ibc channel channels
# 旧 channel 仍 OPEN
```

`med q staking params` / `validators` 在 v3 由 `x/wstaking` 自定义 query 提供；若命令缺失，说明没用带修复的 v3 二进制。

## 7. Phase C — RollApp / dymint 升级

Hub 已在 v3 出块、旧 channel 仍在之后，再动 RollApp 数据目录。

### 7.1 备份

```bash
cp -a "$HOME/.rollapp" "$HOME/.rollapp.bak-$(date +%Y%m%d%H%M)"
```

### 7.2 离线 3D store 迁移

迁移读写 `~/.rollapp/data` 下的 dymint DB。`--rollapp-param-da` **默认是 `celestia`**，ME 测试网必须显式指定 `me-da`（与 `dymint.toml` 的 `da_layer` 一致）。

```bash
# 确认节点已停
dymint run-3d-migration \
  --home "$HOME/.rollapp" \
  --rollapp-param-da me-da
```

成功输出：

```text
3D dymint store migration successful
```

若报 `3D migration is not needed`：store 里 `DrsVersion != 0`，说明已经迁过，不要再跑。

迁移还会：

- 把 DA、DRS 写入 `RollappParams`
- **把 proposer 置 nil**，新进程启动时从 Hub 重新拉 proposer（依赖 Phase B 的 sequencer 索引回填）

### 7.3 配置

新 dymint 的 `dymint.toml` 键名可能比旧文件多（P2P gossip、block sync、sequencer set 更新间隔等）。建议：

1. 用新 `rollappd` 在临时目录 `init` 一份默认 `dymint.toml`
2. **只把** settlement / DA / keyring / gas 从旧文件抄过来
3. 不要覆盖整个文件导致 DA 变回 `celestia` 或 settlement 变 `mock`

核对：

```toml
settlement_layer = "me-hub"
settlement_node_address = "http://127.0.0.1:36657"
da_layer = "me-da"
```

`max_idle_time` 仍须小于 Hub IBC trusting period。

### 7.4 启动新 rollappd

```bash
ln -sf /usr/local/bin/rollappd-v3 "$(go env GOPATH)/bin/rollappd"
rollappd start
```

验收：

```bash
# RollApp 本地出块
rollappd status

# Hub 上 state update 恢复
med q rollapp latest-state-info "$ROLLAPP_CHAIN_ID"
# 高度应继续增加

# 业务回归
rollappd q checkin list-check-in-record
rollappd q kyc list-kyc-credential --limit 3
```

## 8. Phase D — lightclient / IBC / relayer

### 8.1 重启 relayer

Hub 已是 IBC v8，用 `main-dym` 的 `rly`：

```bash
rly start hub-rollapp
```

必要时：

```bash
rly tx update-clients hub-rollapp
```

### 8.2 Canonical client

```bash
med q lightclient expected
med q lightclient light-client "$ROLLAPP_CHAIN_ID"
med q ibc client state 07-tendermint-<N>
```

把 client 的 trust level / trusting period / unbonding period / max clock drift 和 `expected` 对比。v3 后 Hub 侧周期字段是 sequencer **notice period**（由旧 unbonding 迁来）。

若升级前没有 IBC：按第 5.4 节顺序新建（client → 等 state update → channel）。Hub relayer 按这个顺序内置支持。

查询：

```bash
med q lightclient light-client "$ROLLAPP_CHAIN_ID"
```

没有 canonical 就不要建 eIBC 用的 transfer channel。

### 8.3 转账回归

1. 沿用升级前的 channel 做 ICS20（最重要）
2. 再测一笔 delayedack / eIBC（若测试网启用）
3. 确认 `transfer_proof_height != 0`，否则 packet 会被当成 GenesisBridge 校验而失败（`missing fields in genesis bridge info`）

## 9. 升级之后才新建 RollApp（v3 CLI）

`scripts/settlement/register_rollapp_to_hub.sh` 和 `setup_settlement.sh` **仍是 v2 参数，升级后不能再用。**

v3：

```bash
# create-rollapp [rollapp-id] [alias] [vm-type]
med tx rollapp create-rollapp myrollapp_12345-1 RollappAlias EVM \
  --init-sequencer "$SEQUENCER_ADDR" \
  --min-sequencer-bond 100 \
  --from sequencer --keyring-backend test \
  --keyring-dir ~/.rollapp/sequencer_keys \
  --fees 200000000umec --gas auto --yes

# create-sequencer [pubkey] [rollapp-id] [bond] [metadata.json]
# metadata 为可选文件；还可 --reward-address / --whitelisted-relayers
SEQ_PUB_KEY=$(rollappd dymint show-sequencer)
med tx sequencer create-sequencer "$SEQ_PUB_KEY" myrollapp_12345-1 100000000000000000000umec metadata.json \
  --from sequencer --keyring-backend test \
  --keyring-dir ~/.rollapp/sequencer_keys \
  --fees 200000000umec --gas auto --yes
```

默认全局最低 bond：`100 mec`（`DefaultMinSequencerBondGlobalCoin`）。bond 不足会被拒。

## 11. 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| halt 后 v3 panic IBC client params | 没跑 upgrade handler / 未 `SetPreBlocker` | 确认二进制含 v3 handler；不要用「v3 genesis 新链」冒充升级 |
| `initial version set to N, but found earlier version 1` | 把 `consensus` 标进 `StoreUpgrades.Added` | 只允许 Added：`lightclient` |
| wasm 启动失败 / 缺 `.so` | libwasmvm v1 vs v2 | 换成 wasmvm v2.1.4 对应动态库 |
| handler 找不到 `v3.0.0` | plan name 写错 | 必须与常量一致 |
| `3D migration is not needed` | 已迁过或 DrsVersion≠0 | 跳过；不要对空目录跑 |
| 迁移后 DA 行为异常 | `--rollapp-param-da` 默认 celestia | 重做前从备份恢复，再指定 `me-da` |
| 新 rollappd 起不来 / proposer 空 | Hub 索引未回填或 settlement RPC 错 | 确认 handler 已 backfill；`settlement_node_address` 指向 v3 Hub |
| IBC packet `genesis bridge` 报错 | `transfer_proof_height==0` | 确认 migrateRollapps 跑过；有 channel 的 rollapp 应被写上 height |
| 升级后 `create-rollapp` 参数错误 | 仍在用 v2 脚本 | 改用 v3：`[id] [alias] [vm-type]` |
| relayer 连不上 Hub | IBC v7 relayer + IBC v8 Hub | 换 `go-relayer` `main-dym` |
| `setup_ibc.sh` 打币失败 | 脚本示例仍是 `udym` | Hub denom 是 `umec` |
| canonical client 为空 | 升级前没有 client，或 client 与 state 对不上 | 按 5.4 节重建：client → state update → channel |
| `goproxy.cn` 404 | 私有 tag 未进代理 | `GOPRIVATE` + `GOSUMDB=off` + `GOPROXY=direct` |

回滚：用 halt 前的 `~/.mechain.bak-*` + `med-v2` 启动（**只能**在尚未用 v3 写出新块、或团队明确接受回滚分叉时）。RollApp 用 `~/.rollapp.bak-*` + 旧二进制。3D migration 是破坏性写库，失败必须从备份恢复，不能「再迁一次」修复。
